Vendredi 0.1.2 moves scenario JavaScript into a WebAssembly sandbox. The desktop app and headless runner both use it. Existing scripts still use JavaScript and the same Vendredi API.

### What changes for scripts

- Each script validation and invocation gets a fresh Wasmtime instance. JavaScript globals last for one call. Use `api.get` and `api.set` for state that should persist for a partner.
- A script can read its incoming message, request replies through its configured partner channel, and write logs and partner state. It has no direct access to host files, sockets, or environment variables. Workspace configuration still determines which files Vendredi reads and where replies go.
- Each call has 32 MiB of guest memory and 50 million units of execution fuel. Script source is limited to 64 KiB, the serialized request to 1 MiB, the result to 256 KiB, and partner state to 64 KiB. A result can request up to 64 sends and 128 log entries. Scripts or interchanges that exceed these budgets can now produce a script error.
- When a script traps or exceeds its limits, Vendredi discards that invocation’s proposed effects and can process the next script.

### Performance

In one local Apple Silicon headless comparison, median time from a warm script command to delivery was 17.3 ms with the sandbox, versus 6.7 ms with v0.1.1. Sampled peak resident memory was 42.4 MB versus 23.9 MB. These measurements cover the full command and a local delivery on one machine.
